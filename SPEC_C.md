# SPEC C: Data Integrity, Audit Trail, and Operating Boundaries

## 1. Scope and implementation outcome

This specification covers immutable use records, invalidation, audit trail, backup, date and time, storage interfaces, operating environment, and delivery evidence. It is binding for the route handlers and server utilities that mutate or query stored data. The browser must never call Google Sheets directly. URS-F-009, URS-F-010, URS-D-001, URS-D-002, URS-D-003, URS-T-001, URS-T-002, URS-T-003, URS-I-001, URS-N-001, URS-N-002, URS-E-001, URS-E-002, URS-E-003, URS-C-001, URS-L-001, URS-L-002.

All write routes must authenticate the httpOnly-cookie session, recheck the actor role and ownership on the server, validate the requested state transition, persist the business change, and append its audit event before returning success. If a required audit write fails, the route must return an identifiable failure and must not claim that the business operation succeeded. URS-F-009, URS-F-010, URS-I-001.

## 2. Use record integrity and invalidation

1. A use record is identified by an immutable nonempty `id`. Its `equipment_id` and `user_id` must reference an existing EQUIPMENT and USERS row. The record view may denormalize names for display, but authorization and linkage use the IDs. URS-D-002.
2. There is no physical-delete route, Sheets delete operation, or UI action for a use record. A request to delete a record must be rejected with an identifiable error. The row and all existing audit rows remain readable after refresh and a new login. URS-F-009.
3. A mistaken record is retained by changing its status to `무효`, never by removing the row. `invalidated_by`, `invalidated_at`, and `invalidation_reason` must be retained with the record where those fields exist, and the matching audit row is mandatory. The invalidation reason is required after trimming whitespace. URS-F-009.
4. Only the owning TESTER may edit or invalidate a record that has not reached `검토완료`. The server must deny a different TESTER, ADMIN, APPROVER, anonymous request, and every request for a `검토완료` record. A `무효` record is not editable or invalidated a second time. URS-F-009.
5. If an invalidated record was `사용중`, the same server transaction path changes the linked equipment occupancy from `사용중` to `미사용`. The response must not report success unless both record and equipment changes succeed. URS-F-009.
6. An edit requires a nonempty modification reason. Before applying the patch, capture a complete stable-key snapshot of every changed business field. Store the original snapshot in `before_value` and the resulting snapshot in `after_value` of the audit row. Do not treat an overwritten row as sufficient historical evidence. URS-F-009, URS-F-010.
7. The server, not the browser, sets `updated_by`, `updated_at`, invalidation data, review data, signature data, and every event timestamp. Client payloads carrying those fields are ignored or rejected. A later modification must not alter original creation, start, end, signature, or earlier audit timestamps. URS-F-009, URS-D-001.
8. Record list and detail routes reread stored rows using the defined server interface with no browser cache. After a successful write, a manual refresh or re-login must show the same retained `id`, latest allowed state, invalidation marker, and audit history. URS-F-009, URS-I-001.

Required negative tests are: physical deletion attempt; blank invalidation reason; blank edit reason; non-owner edit; edit of `검토완료`; a second invalidation; forged server-assigned timestamp; and invalidation of a `사용중` record without releasing equipment occupancy. Each must be rejected without an unintended data change. URS-F-009, URS-N-001.

## 3. AUDIT tab data contract

The `AUDIT` tab has exactly these application-owned columns, in this logical meaning: `id`, `category`, `actor_id`, `actor_name`, `role`, `action`, `target`, `before_value`, `after_value`, `reason`, `timestamp_kst`. `id` is unique and generated by the server. Every column is populated with a value or an intentional empty string. `timestamp_kst` stores an ISO 8601 instant produced by the server and is rendered in KST by `lib/kst.ts`; its header is retained for compatibility with the required display semantics. URS-F-010, URS-D-001, URS-T-002.

| Column | Required mapping and rule |
|---|---|
| `id` | Immutable unique audit-event identifier. It must not be reused. URS-F-010. |
| `category` | `SECURITY`, `DATA`, or `SYSTEM`. `SYSTEM` is an implementation default for backup events. URS-F-010, URS-D-003, URS 근거 없음, 기본값. |
| `actor_id` | Authenticated user ID. Failed unknown login uses `UNKNOWN`; scheduled work uses `SYSTEM`. URS-F-010, URS-D-003. |
| `actor_name` | Current actor name or `Unknown`/`System` where no account session exists. It must not contain a password. URS-F-010. |
| `role` | Actor role at the event time, or `ANONYMOUS`/`SYSTEM`. This preserves the security context even if a later account role changes. URS-F-010. |
| `action` | Stable event code from section 4, optionally followed by a Korean display label. It is the required 행위 and enables event-type filtering. URS-F-010. |
| `target` | `TYPE:id` plus a concise display identifier, for example `USAGE:REC-001` or `EQUIPMENT:EQ-001`. It is the required 대상 기록. URS-F-010, URS-D-002. |
| `before_value` | Stable-key JSON snapshot of changed fields before mutation. Empty only when no prior business value exists. Password values are never written here. URS-F-009, URS-F-010. |
| `after_value` | Stable-key JSON snapshot of changed fields after mutation. Empty only where there is no resulting business value. Password values are never written here. URS-F-009, URS-F-010. |
| `reason` | Required for edit, invalidation, exceptional termination, review change request, and resume rejection. It remains present for other events as an empty string or a non-secret explanatory value. URS-F-009, URS-F-010. |
| `timestamp_kst` | Server-assigned event instant. It is immutable and displayed as `YYYY-MM-DD HH:mm:ss (KST)`. URS-F-010, URS-D-001. |

`AUDIT` is append-only through the application. No route may expose edit, delete, or arbitrary client insertion for this tab. The shared server audit helper appends events; callers cannot choose a false actor, time, or target. Google Sheet access is limited to the configured service account and approved administrators outside the application boundary. This application can guarantee append-only behavior only through its API and service-account permissions; manual edits by spreadsheet owners are an external operational risk. URS-F-010, URS-T-002, URS-I-001, URS-C-001.

Audit read access is limited to ADMIN and APPROVER. The audit list supports server-side filters for inclusive KST date or date-time range, actor ID, and action/event type, with category as an additional default filter. Empty filters return the permitted full history. TESTER access is denied and recorded as `SECURITY.ACCESS_DENIED`. URS-F-010, URS 근거 없음, 기본값.

The audit report uses the currently applied filters and includes every matching row. ADMIN and APPROVER may print it. The print view uses `AuditPrintTable`: summary fields are timestamp, category, actor, role, and action; target, complete before value, complete after value, and reason are printed in the record detail block. Before the browser print dialog opens, append `PRINT.AUDIT_REPORT_PRINTED` with the filter set in `after_value`. A logbook print appends `PRINT.LOGBOOK_PRINTED` with the equipment and period. URS-F-010, URS-F-007, URS 근거 없음, 기본값 for audit-report print auditing.

## 5. Date, time, and display rules

All persisted system timestamps use an ISO 8601 instant generated in the Node.js server. They are not accepted as authoritative client input. Every screen and print output renders all system timestamps in KST through `lib/kst.ts` as `YYYY-MM-DD HH:mm:ss (KST)`, 24-hour clock. Seconds are mandatory because URS-D-001 is more specific than the general design default without seconds. URS-D-001, URS-F-009.

This rule applies to created, updated, invalidated, exceptional-termination, request, approval, rejection, second-person verification, review, electronic-signature, login, logout, account unlock, password reset, security-setting change, audit, print, backup, and seeded record timestamps. User-entered date-only fields, such as calibration validity date, use `YYYY-MM-DD`; they are not displayed as fabricated times. URS-D-001, URS-F-009, URS-F-010, URS 근거 없음, 기본값 for the date-only exception.

Audit lists reserve at least 200px for the seconds-inclusive timestamp. The full timestamp remains visible in detail modal and printed report. The list has a manual refresh action and no polling. URS-D-001, URS-F-009, URS 근거 없음, 기본값.

## 6. Backup, storage, and external boundaries

All relevant data, including EQUIPMENT master data, use records, electronic-signature fields, AUDIT, USERS, role and permission settings, security settings, training profiles and history, remediation and resume records, and backup metadata, is exported from the operating Google Spreadsheet as one `.xlsx` workbook. ADMIN alone may start the backup with a mandatory execution reason. The latest user request supersedes both the original `01:00` automatic schedule and the later `13:00` configurable schedule, so this is a **URS 개정 대상**. URS-D-003, URS-T-002, URS 개정 대상.

No server scheduler creates a backup because a browserless process cannot save a file to a user PC. `vercel.json` contains no backup Cron, `GET /api/cron/backup` returns `410 Gone`, and legacy automatic settings are seeded disabled without deleting existing sheet columns or rows. URS-D-003, URS-T-003, URS-C-001, URS 개정 대상.

The server exports the workbook into memory and returns it in the authenticated `POST /api/backup` response with XLSX content type, attachment disposition, no-store cache control, file name, and backup ID headers. The client reads the response as a Blob, creates a temporary object URL, invokes an anchor with the `download` attribute, and immediately revokes the URL. No XLSX blob is uploaded to a system Google Drive path or persisted by the application. The first completed file on a KST date is `Back-Up YYYY-MM-DD.xlsx`; additional same-date files use `Back-up YYYY-MM-DD_HH-mm-ss.xlsx`. `BACKUP_RUNS` stores metadata and SHA-256 while the legacy Drive file ID remains blank. URS-D-003, URS 개정 대상.

Every completed or failed run immediately appends a `BACKUP_ALARMS` row. Only ADMIN may see backup alarms, the backup page, the backup APIs, or start a download. The backup page shows backup date, start, completion, status, scope, format, file name, size, error, and `사용자 PC` as the completed storage method. Historical runs and alarms do not expose a download link because no application-side file exists. The legacy `GET /api/backup/[backupId]/download` route returns `410 Gone` and instructs the user to generate a new backup. URS-D-003, URS 개정 대상.

Backup verification must show: ADMIN-only route access, complete XLSX scope, no Drive file creation, both file-name patterns, persisted size and SHA-256 metadata, a browser download to the user PC after generation completes, blocked legacy scheduler and historical download routes, immediate success and failure alarms, and restoration of the downloaded workbook without overwriting live data. Until the browser save and restoration are verified in deployment, the external portion remains `environment_pending`. URS-D-003, URS-T-003, URS-C-001, URS 개정 대상.

The browser calls only `/api/*` using `cache: "no-store"`. Route handlers use the defined Google Sheets server API and no client-side Sheet credential or direct Sheet call. Every data route declares `dynamic = "force-dynamic"`, `revalidate = 0`, and `runtime = "nodejs"`. Google Sheets availability, service-account sharing, network access, and browser download behavior are external dependencies. If Sheets is unavailable, routes return a safe identifiable service error, preserve no partial-success claim, and provide a manual retry path. URS-I-001, URS-T-002, URS-C-001, URS-N-001.

The supported operating environment is an internet-connected training-room PC using a current Chrome-class browser. The deployed application must be reachable by URL. Validate the intended Chrome version and, where print support is claimed, Chrome and Edge. Firefox print limitations must not hide required information. URS-E-001, URS-T-001, URS-T-003.

## 8. Nonfunctional, lifecycle, and delivery evidence

Server and client validation must turn missing required values, malformed IDs or dates, unsupported state transitions, forbidden roles, forbidden ownership, invalid date ranges, and unavailable storage into one identifiable Korean error message. It must not expose a stack trace, Sheet credential, private key, token, or raw Google API error. The client must also render the server rejection as a visible error banner. URS-N-001, URS-I-001.

For normal conditions, measure navigation to each primary page and its first required data response from a Chrome-class browser. The target is complete primary screen transition within five seconds. Record the route, test data size, measured duration, browser, and result. A Sheets outage is an availability dependency and must be reported separately, not silently counted as a successful transition. URS-N-002, URS-C-001.

Every code, configuration, schema, or operational change requires a documented change-control entry before use. It identifies the change, reason, affected clause IDs, impact assessment, verification evidence, approver, and effective date. Maintain user training completion in a durable training-history row before the user performs operational use. The exact training-history fields are `URS 근거 없음, 기본값`: `id`, `user_id`, `course_name`, `completed_at`, `recorded_by`, `status`. URS-L-001, URS-L-002.
