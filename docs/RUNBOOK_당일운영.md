# RUNBOOK: 교육 당일 운영 절차 (강사용, 2쪽, Codex 조)

전체 흐름과 조별 지시 문장은 `docs/GUIDE_실습흐름_URS에서VSR까지.md`에 있다. 이 문서는 강사가 시간대별로 확인할 것과
막혔을 때의 처치를 적는다.

## 1일차 15:20 첫 구현 (원샷 빌드, 60분)

### T-10분, 조별 사전 점검
1. Codex 앱에서 조별 폴더를 열거나 터미널에서 `codex -C . -s workspace-write -a never`로 시작한다(SETUP "Codex 실행" 절).
2. `.env.local` 존재 확인(없으면 SETUP ⑤. 없어도 빌드는 진행되고 스모크만 생략됨).
3. **배정 URS 투입**: 조가 확정한 URS `.docx`를 `docs/urs/`에 넣는다(사전 변환본이 있으면 `docs/urs/*.md` 존재만 확인).
4. `npm.cmd run check:harness`가 `TEMPLATE_READY`이고 모델 라우팅 검사가 통과하는지 확인한다. 해당 계정에서 Sol, Terra와 Terra/xhigh를 사용할 수 있는지는 별도로 확인한다. 작업 폴더 쓰기가 막히면 Codex의 workspace 설정을 확인한다.

### T-0, 트리거

```
하네스 절차대로 URS MVP 빌드를 시작해.
```

- Codex는 AGENTS.md를 자동으로 읽고 `.codex/agents/`의 7개 사용자 정의 역할을 사용한다. Analyzer는 Terra/xhigh, Builder는 Sol/high이며 오케스트레이터는 Sol/high다. Terra/low 보조 기본값을 핵심 역할 대신 사용하거나 Luna로 바꾸지 않는다. 실제 슬롯 수에 맞춰 병렬 웨이브를 사용하고, 사용자 정의 역할을 선택할 수 없으면 `agent:prompt` 폴백 또는 오케스트레이터의 Sol/high 순차 처리를 사용한다.
- 세션이 끝나거나 새 세션으로 바뀌면 `하네스 상태 파일을 읽고 마지막 미완료 단계부터 계속해.`라고 입력한다. 처음부터 다시 분석하지 않는다.
- 60분 타이머 시작. 예산: STEP 0(3분) → 1(6분) → 2(6분) → 3(33분) → 4(12분). 진행 중 출력은 영어, 완료 보고와 산출물은 한국어 보고용 문체로 나온다.

### T+60분 (16:20), QA와 수정 요청 (1일차 안에)
1. Codex 보고에서 계정표와 기동 URL 확인 → `/api/seed` 호출 → 로그인 화면에서 계정 선택(비밀번호 1234 자동 입력)으로 로그인 시연.
2. `npm.cmd run harness:sync`와 `npm.cmd run check:harness -- --final` 결과를 확인한다. `INCOMPLETE`이면 남은 구현 가능한 조항을 계속 처리한다.
3. `IMPLEMENTED.md`, `docs/generated/URS_TRACEABILITY.md`, `URS_EVIDENCE.md`, `URS_GAPS.md` 존재 확인. 이 파일들이 FDS 작성과 RTM 실습의 입력이다.
4. 보고의 남은 항목과 사유를 조와 함께 읽고, 수정 요청으로 풀 것과 URS 개정으로 풀 것을 나눈다.
5. 개발 서버를 켠 상태에서 조가 QA를 하고 수정 요청을 반복한다(GUIDE 2.2.2 ~ 2.2.4). 조원은 개인 PC로 Network 주소에 접속해 함께 QA 한다.
   강사는 조별로 확인한다: 역할별 로그인으로 권한 매트릭스가 맞는지, 대표 차단 규칙이 서버에서 막히는지(화면만 막는 구현이면 수정 요청), 감사추적에 남는지.
   수정 요청은 한 번에 하나. "URS 외 요청"으로 분류된 항목은 URS 개정 논의 소재로 남긴다.
6. **1일차 운영 종료 조건**: 6개 조 모두 개발 서버에서 자기 시스템의 대표 흐름이 동작하는 것을 확인했다. 지연 조는 `INCOMPLETE` 상태와 남은 조항을 명확히 인계하며 하네스 완료라고 보고하지 않는다.

## 2일차 10:25, FDS 작성 (AI Agent가 공급자 역할로, Word 출력)

1. 남은 수정 요청이 있으면 먼저 끝낸다(13:20 구현 완료 전까지 바뀌는 코드는 FDS 재작성 대상).
2. `check:harness -- --final`이 통과한 조가 AI에게 `FDS를 작성해줘`를 요청한다. AI가 코드의 현재 상태로 `docs/FDS.md`를 쓰고 `npm.cmd run fds`로 `docs/KPBMA-EDU-00X-FDS_N조_시스템명_v1.0.docx`를 만든다(약 15분).
3. 강사 확인: 채팅 보고의 "ERROR 0건", "구현 조항 n/m 건 연결"(m/m 이어야 함), 미구현 제외 조항 수. 연결되지 않은 조항이 있으면 `연결되지 않은 조항을 FS 행에 추가해줘`.
4. Word에서 열어 목차 갱신(예) → 표지의 검토자와 승인자 기재 → 조원이 자기 담당 조항의 FS 행을 읽고 코드 동작과 맞는지 확인(공급자 문서를 사용자가 검토).
5. 11:00 DQ Matrix: 개인 담당 10개 조항에 대해 `DQ 대조표를 만들어줘 (조항 ID 목록)` → DQ Matrix(xlsx)에 Pass, Fail, C/P와 FS/DS ID 기재.

## 2일차 13:20, 구현 완료와 푸시, 배포

1. DQ까지 마친 조부터 배포한다. 배포 전에 각 계정의 비밀번호를 1234에서 바꾸게 한다(비밀번호 변경 화면). DQ 이후 코드를 고쳤으면 `FDS를 다시 작성해줘`(v1.1).
2. 조가 AI에게 `커밋해.`를 요청한다. AI가 `.env.local`과 키 파일 제외, `npm.cmd run check:harness -- --final`과 `npm.cmd run build` 통과를 확인한 뒤 커밋과 태그를 만들고
   사람이 실행할 명령을 안내한다. 조원이 터미널에서 `git push origin main --tags`를 직접 실행한다(AI는 푸시하지 않는다).
   푸시가 곧 Vercel 배포다(강사가 사전에 GitHub 리포와 Vercel 프로젝트를 연결해 둔다, SETUP ⑥).
3. 배포 URL에서 `/api/seed` → 로그인 확인. AI가 커밋 준비 때 만든 태그 v1.0이 함께 푸시되었는지 `git tag`로 확인한다. 이 URL과 버전이 IOQ 대상이다.
4. 배포 후 코드 변경은 변경관리로 다룬다(CHANGELOG 기록, 재배포, 영향 시험 재수행).

## 2일차 14:10 IOQ 시나리오, 15:00 IOQ 수행, 15:40 RTM과 VSR

- IOQ는 배포 URL에서 수행한다(로컬이 아님). 시나리오 초안은 `IOQ 시나리오 초안을 만들어줘 (담당 조항 ID 목록)`. QA 중 추가된 URS 외 기능은 IOQ 대상에서 제외한다.
- RTM은 `IMPLEMENTED.md`, `docs/FDS.md`의 FS/DS ID와 `RTM 입력을 정리해줘`의 결과에서 시작한다.
- 발표(16:15)는 같은 시스템을 다른 도구로 만든 두 조를 나란히 시연한다.

## 자주 나오는 증상 → 처치

| 증상 | 처치 |
|---|---|
| 로그인 화면에 "환경 변수 미설정" 노란 배너 | `.env.local` 작성 후 dev 재시작 (SETUP ⑤) |
| `/api/seed` 403 또는 500 | 시트 편집자 공유, Sheets API 활성화 확인 (SETUP ②④) |
| 429 quota 초과 | 화면 새로고침 연타 중지, 1분 대기. 폴링 코드가 생겼는지 확인(금지 규칙) |
| Vercel에서 데이터가 안 보임 | 새 페이지에 3종 export(`force-dynamic` 등) 누락 여부 확인. Vercel 환경 변수 3종과 재배포 확인 |
| `AGENTS.md` 끝에 `nextjs-agent-rules` 블록이 생김 | `npm.cmd run check:harness`로 전체 지시 크기를 확인한다. 공식 기본 한도에 가까우면 해당 블록을 제거하고 새 Codex 세션에서 루트 지시를 다시 읽게 한다 |
| Chrome이 로그인 때 "비밀번호 변경" 경고를 띄움 | 초기 비밀번호 1234가 유출 목록에 있어 뜨는 브라우저 기능이다. 확인을 눌러 닫고 진행한다(QA 편의를 위한 의도된 값). 배포 전 비밀번호 변경 후에는 뜨지 않는다 |
| 변환본에 조항 ID가 없음(빈 셀) | URS의 ID가 Word 자동 번호. 텍스트로 바꿔 다시 넣거나, 에이전트가 임시 부여한 ID를 DECISIONS.md에서 확인한다 |
| 에이전트가 새 패키지를 설치하려 함 | `패키지 추가 금지 규칙이야. 있는 것으로 구현해.` |
| 커밋에 `.env.local`이나 키 파일이 포함될 뻔함 | 즉시 중단. `npm.cmd run check:commit`으로 확인, `.gitignore` 확인, 이미 추적 중이면 `git rm --cached <파일>` |
| AI가 `git push`를 하려 함 | 규칙 위반. `푸시는 사람이 한다. 커밋까지만 해.` |
| 패치 적용 실패가 반복됨(context mismatch) | 최신 파일을 다시 읽고 더 작은 패치로 적용한다. 역할이 파일 전체를 소유할 때만 전체 재작성을 사용한다. 줄바꿈이 CRLF로 바뀌었는지 확인한다 |
| 서브에이전트 결과가 중간에 끊김 | `서브에이전트가 완료 보고를 낼 때까지 기다려. 예산은 중단 기준이 아니야.` |
