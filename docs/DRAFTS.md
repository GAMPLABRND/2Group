# 문서 초안 지원 (DQ, IOQ, RTM)

AGENTS.md의 CSV 문서 초안 모드 상세 지침이다. 교육생이 CSV 문서를 쓸 때 옮겨 적을 초안을 만든다.
FDS는 별도 FDS 모드(`docs/FDS_GUIDE.md`)로 Word 문서를 직접 만든다. 아래 초안은 모두 `docs/FDS.md`의 FS/DS 표를 근거로 한다.

## 공통 규칙
- 근거 파일은 `docs/FDS.md`, `PLAN.md`, `IMPLEMENTED.md`, `CHANGELOG.md`, 코드다. URS는 조항 ID 확인이 필요할 때만 읽는다.
- 산출물은 한국어 보고용 문체("~입니다", "~하였습니다")로 쓰고, 방점과 대시를 쓰지 않으며, URS 조항 ID를 반드시 병기한다(AGENTS.md 2절).
- 결과는 `docs/` 아래 md 파일로 저장하고, 채팅에는 파일 위치와 표의 행 수, 주의할 점만 한국어로 짧게 보고한다.
- 초안은 참고용이다. 최종 문서는 교육생이 배포된 CSV 문서 양식(Word, Excel)에 옮겨 적고 검토한다. 초안에 그 문장을 첫 줄에 적는다.
- 교육생은 개인 담당 URS 10개를 끝까지 책임진다. 요청에 조항 ID 목록이 있으면 그 조항만 만들고, 없으면 전 조항을 만든다.

## 요청별 산출물

| 요청 문장 | 산출 파일 | 내용 |
|---|---|---|
| "DQ 대조표를 만들어줘" | `docs/DQ_DRAFT.md` | URS 조항 ID별로 `docs/FDS.md`의 FS/DS ID(절 번호 병기, 예: FS-012 (3.2))와 구현 위치를 대조한 표, 미충족 항목과 사유. DQ Matrix(xlsx)의 Design Document 열에 옮겨 적는 형식 |
| "IOQ 시나리오 초안을 만들어줘" | `docs/IOQ_DRAFT.md` | 시험 항목별(설치 확인, 접근 통제, 기능 확인, 감사추적, 전자서명, 데이터 리포팅과 전자기록, 백업과 복구) 시험 단계 표: 단계, 조작, 기대 결과, 근거 조항 ID와 FS ID, 비정상 조건 시험(NT) 여부. 차단 규칙마다 NT 단계를 하나 이상 넣는다. 설치 확인은 배포 URL, 버전 태그, 환경 변수 3종 이름, 시트 탭 구성을 확인하는 단계로 쓴다 |
| "RTM 입력을 정리해줘" | `docs/RTM_INPUT.md` | URS 조항 ID ↔ FS/DS ID(절 번호 병기) ↔ IOQ 시험 항목 번호 ↔ 구현 상태(IMPLEMENTED.md의 상태와 일치) |

## 작성 요령
- FS/DS ID는 `docs/FDS.md`에 있는 번호를 그대로 쓴다. 새로 매기지 않는다. FDS가 없으면 먼저 "FDS를 작성해줘"를 안내한다.
- 미구현과 부분 구현 조항은 DQ와 RTM에 "미구현(사유)"로 남기고 숨기지 않는다. 사유는 IMPLEMENTED.md의 문장을 그대로 옮긴다.
- IOQ 단계의 기대 결과는 화면에 보이는 문구와 시트에 남는 값을 구체적으로 쓴다(예: "저장이 차단되고 '종료일시는 시작일시 이후여야 합니다.'가 표시된다. 시트에 행이 추가되지 않는다").
- IOQ는 배포 URL에서 수행하므로 시나리오의 접속 주소는 배포 URL로 쓴다. QA 중 추가된 URS 외 기능은 IOQ 대상에서 제외한다.
- RTM 입력은 URS 7.1의 모든 조항이 한 행씩 있어야 한다.
